# ADR 0003: Unknown broadcast outcome

Status: Accepted design.

Before any send, commit the exact signed bytes, locally computed hash, nonce, and an `UNCERTAIN` broadcast claim. A timeout, lost HTTP response, process death, malformed response, or ambiguous RPC error leaves the attempt uncertain. It never creates another intent, allocates another nonce, or treats a null lookup as proof of nonacceptance.

On recovery, query `eth_getTransactionReceipt` and `eth_getTransactionByHash` for **every** signed attempt through healthy endpoints. Match returned chain, hash, sender, nonce, and call fields. A matching transaction proves provider visibility; a matching receipt anchored to a canonical block proves inclusion at that observation. A null response proves only that this provider cannot currently show it. Read `latest` and `pending` counts as diagnostic evidence; `latest > nonce` without a known canonical receipt triggers external-consumption investigation. Multiple nulls and a low pending count do not prove nonacceptance.

When no matching transaction/receipt or nonce conflict is found, rebroadcast the **identical persisted bytes** of a signed attempt to eligible endpoints. A matching hash acknowledgment or matching lookup can advance to `PENDING` as provider acceptance/visibility evidence; an already-known error requires a matching lookup. An error string alone is never confirmation. If an endpoint says underpriced or nonce too low, recheck the local hash and chain evidence before taking further action. Use bounded backoff, send count, and reconciliation deadline. At deadline, `BLOCKED` with `OUTCOME_UNRESOLVED` preserves the bytes and work for operator review; no new business request is inferred. A matching receipt can now record a provisional winner, and replacement uses a separate bounded claim. Canonical block verification and confirmation progression are implemented by the separate receipt service described in ADR 0006.

The exact raw attempt can be rebroadcast while chain ID/anchor match, no different canonical transaction has consumed the nonce, and the configured fee and endpoint policies permit submission. Repeating identical bytes cannot change call semantics, but multiple signed attempts with the same nonce can race. A fee replacement is a separate guarded decision under ADR 0004. Evidence categories: (A) existence: matching hash returned or observed at a provider; (B) inclusion and confirmation: matching receipt, canonical block, required depth; (C) current non-observability: null at queried providers; (D) uncertainty: anything short of B when history/visibility is incomplete. One provider's success does not imply durable propagation or finality.
