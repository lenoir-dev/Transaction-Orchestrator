# Persistence implementation

The `internal/orchestrator` package provides `ProvisionAccount`, `CreateIntent`, `GetIntent`, `ReserveNonce`, `Block`, `Resume`, `FailUnreserved`, `RecoverableIntents`, `SignInitial`, `LoadSignedAttempt`, `AdvanceBroadcast`, `BroadcastStatus`, and `BroadcastMetrics`, `SignReplacement`, `AttemptHistory`, `ObserveWinner`, `ReplacementMetrics`, `ReconcileReceipts`, `ReceiptWork`, `ReceiptHistory`, `ConfirmationStatus`, `ConfirmationMetrics`, `ConfirmationHistogram`, and `ReceiptReady`. It is a library; the HTTP API remains a contract. See [architecture](architecture.md) for signer and broadcast boundaries.

Configure a PostgreSQL connection pool and apply the ordered migrations starting with `migrations/001_initial.sql` to the target database. For a network-managed account, register its chain ID and signer identity/address without a seed; account reconciliation initializes the nonce from agreeing eligible `pending` views before allocation. The legacy `ProvisionAccount` operation accepts an externally verified seed and retains `TRUSTED_SEED` status for controlled fixtures and existing integrations. It never changes an existing cursor. Chain identity is data, not a compiled network selection. See [ADR 0007](adr/0007-rpc-runtime.md).

Create requests include a tenant scope and idempotency key. The caller that invokes the library must authenticate and derive the tenant. Canonical digesting normalizes decimal quantities and hex bytes; a duplicate key and matching request retrieves the existing intent with its original policy snapshot. A conflicting request returns `ErrConflict`. The database unique constraint decides concurrent insert races. The library accepts resolved gas limit, confirmation depth, fee ceilings, replacement limit, and policy version as configuration per new intent; it does not set deployment defaults. The replacement call supplies its clock, positive bump basis points, interval, signer and observation deadlines; no deployment default is imposed.

Nonce reservation locks the account row and writes cursor, reservation, intent state, and audit event in one short transaction. Concurrent replicas share that lock and the unique `(chain_id, signer_address, nonce)` constraint. A repeat reservation of the same reserved intent returns its nonce. Blocking an already reserved intent pauses new allocation on that account; resuming it retains the nonce. A created intent may fail before reservation; a reserved intent cannot be marked terminal through the pre-sign failure method. Recovery lists nonterminal rows and their reservations after reopening the pool.

The full future lifecycle is specified in `SPEC.md`. The package persists `RESERVED → SIGNING → READY → UNCERTAIN → PENDING`, with guarded `BLOCKED` states. A durable broadcast claim precedes RPC; restart queries the local hash before any retry and preserves all signed attempts under one nonce. `PENDING` is acceptance or visibility evidence, never finality. Bounded replacement can return to `SIGNING` and `READY`; a block-validated receipt records `MINED`. The receipt service advances `CONFIRMING`/`CONFIRMED`, records orphaned evidence and resumes shallow reorg reconciliation.

Run `make verify-phase6` with `TXORCH_TEST_DATABASE_URL` pointing to a disposable PostgreSQL 18 database and `TXORCH_ANVIL_BINARY` pointing to Anvil 1.8.5. The integration tests create and drop their own schemas, execute all six migrations, start ephemeral local chains, and use generated fixture keys. Without either variable, ordinary `go test` skips integration; the full verification target fails. The operator needs `CREATE` on the database and ownership of the test schemas. Do not use a production database for these tests.

Resolve confirmation depth from chain configuration when creating each intent. Provide the explicit receipt clock, interval, read deadlines, attempt bound and reorg window on each poll. The first poll stores the reorg window; later changes are rejected. Keep polling confirmed inclusions through `ReceiptWork` to discover a later supported reorg. A deep incident requires an operator resync policy; a generic resume does not clear its account readiness flag.
