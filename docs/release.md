# Local release evidence

`make verify-release` is the single local release gate. It runs integration and correctness checks against disposable PostgreSQL 18.6 databases and official Anvil 1.8.5, then fuzz smoke, Linux cross-builds, Docker checks, govulncheck, Trivy filesystem and image scans, CycloneDX SBOM checks, and a replay from a clean local Git clone. The filesystem scan excludes the generated `.cache/` Go build and module cache; it scans the release source, while the image scan checks the built runtime image. It writes generated evidence under ignored `dist/` and `artifacts/` paths. The exact source-tree checksum is computed by `scripts/source_identity.py`; it is independent of Git.

The Linux binaries are built with `CGO_ENABLED=0`, `-trimpath`, and an embedded source checksum in the pinned Go Docker builder. `dist/SHA256SUMS` covers binaries, CycloneDX SBOMs, scanner results and `provenance.local.json`. The provenance is **unsigned local provenance**: it records build commands, dependency file hashes, tool versions, artifact hashes and the local gate outcome. It is neither an SBOM nor a signed attestation. A fresh build may produce different binary hashes if the build toolchain or dependency cache changes; verify the recorded source identity and checksums for the actual outputs.

The release gate needs Go 1.27.2, PostgreSQL 18.6 command-line tools, Docker, Python 3, Syft 1.54.0, Trivy 0.75.0 and govulncheck 1.8.0. The local runner downloads the official Anvil 1.8.5 archive and checks its SHA-256 when `TXORCH_ANVIL_BINARY` is not supplied. The Docker health fixture checks official Anvil and Forge 1.8.5 against PostgreSQL 18.6, then probes the runtime image's live and ready endpoints. Local fixtures use public development keys only. The runtime image is distroless and configured as UID/GID 65532; the included server itself requires explicit development mode, loopback RPC and caller-provided credentials.

The local Trivy image scan reported `DLA-4792-1` with severity `UNKNOWN`: the pinned Debian 12 distroless image has `tzdata` 2026b and the advisory lists 2026c as the fix. This is a timezone database update, with no described exploit or affected transaction path; the service does not perform calendar or local-time scheduling. The finding remains visible in the machine-readable scan report. Refresh the pinned base image and rescan when its corrected package is available.

## Publication checks

For each published commit, confirm that the remote HEAD and hosted Linux CI run refer to that exact source revision. Inspect the hosted test, scan, SBOM, and artifact output, and reproduce the local release gate from a clean checkout. A GitHub Release requires a separately chosen version and reviewed release artifacts; this repository does not define a release version. No production deployment or independent audit is claimed.
