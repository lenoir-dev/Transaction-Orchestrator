# Persistence and transaction boundaries

`migrations/001_initial.sql` establishes the PostgreSQL schema; `002_signed_attempts.sql` adds attempt identity, immutable snapshots, and deferred signing-state alignment; `003_broadcast.sql` adds send counters, scheduling fields, state alignment, and durable observations; `004_replacements.sql` adds successor lineage, bump metadata, same-nonce/call constraints, and an unsent historical status without rewriting prior migrations. `005_receipt_finality.sql` adds `CONFIRMING`, receipt verification metadata, bounded poll scheduling, immutable inclusion identity, and competing receipt/head block history. `006_runtime_accounts.sql` adds durable account reconciliation, nonce conflict evidence and runtime retry scheduling. Chain quantities and wei use nonnegative decimal `numeric`; nonce uses `numeric(20,0)` constrained to uint64 range; addresses, hashes, calldata, and exact signed transaction use `bytea`; time uses `timestamptz`. The signer account row is the per-chain/account lock and high-water cursor. The reservation table never deletes a nonce in v1. Integration tests apply all six migrations to isolated PostgreSQL schemas.

The database enforces tenant/key uniqueness, account and nonce uniqueness, one immutable reservation per intent, a monotone account nonce cursor, attempt identity, matching reservation nonce, foreign keys, state and quantity domains, immutable intent and attempt construction fields, signed byte/hash immutability, and deferred alignment of active signing states. Application code enforces canonical request equivalence, authorization, signed transaction decode/hash/sender/call comparison, fee ceilings, fenced claims, and audit entry on each transition. The receipt service validates canonicality using RPC block evidence; PostgreSQL preserves that evidence and its history. A CHECK constraint cannot validate a cryptographic signature. Restrict roles and backups carrying signed bytes; application-level encryption is not implemented.

| Boundary | Inside one short DB transaction | Outside transaction |
| --- | --- | --- |
| Create intent | Unique tenant/key insert or locked existing-row digest comparison, audit | Authentication and policy validation |
| Reserve nonce | Lock signer account; validate local cursor and pause flag; insert reservation; advance cursor; set `RESERVED`; audit | Network-managed calls reconcile `latest`/`pending` through eligible endpoints before reservation; explicit-seed calls rely on the supplied trusted seed |
| Prepare attempt | Lock/fence intent; insert `PREPARING` attempt and policy/fee snapshot; set `SIGNING`; audit | Fee/head reads and signer invocation |
| Persist signature | Match lease token, decode/check signed result, write bytes/hash and `READY`; audit | Signer call; no send until commit succeeds |
| Claim/send | Persist `UNCERTAIN` and fenced claim, then record a bounded send slot; audit | Send exact stored bytes to an eligible endpoint |
| Observe | Conditional fenced update of hash/receipt visibility, state, reason, audit | Hash/receipt/block/head/latest nonce reads before receipt/winner/progress transactions |

Claim/send and hash/receipt/nonce observation cover the active signed attempt and all historical hashes for winner detection. Network-managed accounts now reconcile before initial nonce allocation; explicit-seed accounts remain a separate trusted path. Receipt canonicality, confirmation depth and bounded reorg handling are implemented. Signing uses explicit fees and gas, so there is no head read in its current prepare boundary.

Use a lease token plus row version to reject stale workers. Reclaim an expired `SIGNING` lease only after checking whether a signed attempt was committed; if no raw bytes were stored, no send was permitted. For replacement, old attempts remain searchable. Encrypt raw bytes with a deployment-managed envelope key; availability of that key is a readiness dependency, and corruption or missing bytes blocks the intent. Never derive a replacement from a mutable prior row. Audit evidence contains bounded summaries and hashes, not secrets or raw transaction bytes. Partition/retention and backup restoration drills are later deployment work; retain idempotency identity and nonce ledger for the full operational lifetime.
