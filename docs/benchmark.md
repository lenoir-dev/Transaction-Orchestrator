# Local benchmark methodology

make benchmark-smoke runs the same correctness-gated integration workload three times in isolated PostgreSQL schemas and ephemeral Anvil chains. Each run creates 12 intents across two development signers, with six intents per signer and concurrent HTTP admission within each signer. Six broadcasts are normal, three lose an accepted response and require exact-hash reconciliation, and three receive one same-nonce replacement. Controlled blocks bring all 12 intents to depth-three CONFIRMED.

The recorded workload includes percentages, signer contention, RPC fault profile, four runtime workers, a 24-connection test pool and four global RPC slots. It records Go, PostgreSQL and Anvil versions, OS, architecture, CPU model, logical CPU count and RAM. Each run records create and reconciliation p50/p95 wall latency, controlled confirmation duration, intents/second, approximate rows/second for the intent/reservation/attempt tables, process CPU seconds, heap allocation and total duration. The runner reports the median intents/second across all runs, with no exclusions.

Before any timing result is accepted, SQL verifies 12 intents, 12 reservations, 15 signed attempts, 12 confirmed states and zero duplicate signer/nonce ownership. Every intent must retain signed raw bytes. The checksum input is intents=12;reservations=12;attempts=15;confirmed=12;duplicate_nonces=0; SHA-256 is d5ea1a086d64324b475256f08b46d40a01a29c0201573d1cacf86c6060e3b967. scripts/phase7_local.py validates every JSON run before producing artifacts/benchmark-runs.json. Failed correctness invalidates the run and suppresses summary throughput.

The benchmark is intentionally small and local. It exercises real PostgreSQL, HTTP, signing and Anvil paths but does not model production chain congestion, remote RPC latency, durable storage contention or a production signer. The numbers are measurements of the recorded host and workload, not an SLA or production capacity claim.
